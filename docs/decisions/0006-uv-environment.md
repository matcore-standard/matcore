# 0006 — uv manages the Python environment

Date: 2026-10-31. Status: accepted. Decided by: Ellad Tadmor.

## Context
Dependencies were declared twice: `environment.yml` (a conda environment, used in local sessions) and `requirements.txt` (used by CI and the README). Nothing kept the two lists in sync, and neither pinned versions, so CI and a local build could run different package versions. pytest was in neither, so `tests/` could not run.

## Decision
1. **uv owns the environment.** Dependencies are declared in `pyproject.toml` and pinned in `uv.lock`, which is generated by `uv lock` and committed. Every command runs through `uv run`. `environment.yml` and `requirements.txt` are removed.
2. **Package name.** The project is named `matcore`. This settles the package name left open in 0004 item 20. `pyproject.toml` has no `[build-system]`, so uv installs only the dependencies, not the project itself, until the tools package (status step 9) is built.
3. **Dependencies.** pyyaml and jsonschema, which the scripts import, are project dependencies. The site and test tools (mkdocs, mkdocs-material, mike, pytest) form a single `dev` dependency group, which `uv sync` installs by default.
4. **CI.** CI installs uv with `astral-sh/setup-uv`, pinned to a release commit hash rather than a tag, and pinned to a uv version. It runs `uv sync --locked`, which fails if `uv.lock` does not match `pyproject.toml`.

## Consequences
CLAUDE.md, the README and `.github/workflows/ci.yml` use `uv run`. Running pytest in CI and pinning the other actions by hash are separate changes.
