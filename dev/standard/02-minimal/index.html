    2.1 Minimal MatCore Metadata

    Version 0.4.0

    The minimal MatCore metadata includes aspects of a dataset deemed important to report for data findability and reuse and are universal across all computational methods. The list of minimal metadata is tabulated below.

    * required   appears at most once   repeatable

    creator*

    An entity (e.g. person, organization, software agent) responsible for generated the dataset and their institutional affiliation if relevant.

    Required Repeatable Type Extent Kind Rec. unit
    yes yes — — — —
    name*

    The name of the entity that generated the dataset.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: A string containing the entity name. Examples: "Albert Einstein", "Lawrence Livermore National Laboratory", "Claude Opus 5.5".

    affiliation

    The affiliation of the entity that generated the dataset if they have one.

    Required Repeatable Type Extent Kind Rec. unit
    no yes — — — —

    Legacy: A string containing the entity affiliation.

    creator-identifier

    A unique, persistent URI that globally and unambiguously identifies the entity that created the dataset.

    Required Repeatable Type Extent Kind Rec. unit
    no yes — — — —

    Legacy: For individuals, this includes an ORCID ID (https://orcid.org), for organizations, an ROR ID (https://ror.org), for software or AI agents, a Digital Object Identifier (DOI) generated specifically for the software code or version (e.g., a Zenodo software DOI) or a Software Heritage ID (SWHID) pointing to the exact software release or state (e.g., swh:1:rel:a0b1c2d3e4f5...).

    affiliation-identifier

    A unique, persistent URI that globally and unambiguously identifies the entity's affiliation.

    Required Repeatable Type Extent Kind Rec. unit
    no yes — — — —

    Legacy: An ROR ID (https://ror.org) or other suitable identifier.

    contributor*

    An entity (e.g. person, organization, software agent) responsible for making contributions to the dataset and their institutional affiliation if relevant.

    Required Repeatable Type Extent Kind Rec. unit
    yes yes — — — —
    name*

    The name of the entity that contributed to the dataset.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: A string containing the entity name. Examples: "Albert Einstein", "Lawrence Livermore National Laboratory", "Claude Opus 5.5".

    affiliation*

    The affiliation of the entity that contributed to the dataset if they have one.

    Required Repeatable Type Extent Kind Rec. unit
    yes yes — — — —

    Legacy: A string containing the entity affiliation.

    contributor-identifier

    A unique, persistent URI that globally and unambiguously identifies the entity that contributed to the dataset.

    Required Repeatable Type Extent Kind Rec. unit
    no yes — — — —

    Legacy: For individuals, this includes an ORCID ID (https://orcid.org), for organizations, an ROR ID (https://ror.org), for software or AI agents, a Digital Object Identifier (DOI) generated specifically for the software code or version (e.g., a Zenodo software DOI) or a Software Heritage ID (SWHID) pointing to the exact software release or state (e.g., swh:1:rel:a0b1c2d3e4f5...).

    affiliation-identifier

    A unique, persistent URI that globally and unambiguously identifies the entity's affiliation.

    Required Repeatable Type Extent Kind Rec. unit
    no yes — — — —

    Legacy: An ROR ID (https://ror.org) or other suitable identifier.

    title*

    A single sentence description of the dataset.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: A string containing the dataset title.

    creation-date*

    The calendar date and time when the dataset was created.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: A string containing the creation date in either format YYYY-MM-DD or YYYY-MM-DDTHH:mm:ssz (where "z" indicates UTC time zone) format (following the ISO 8601 Date and Time Format Standard).

    description*

    A synopsis of the dataset, its contents, and purpose.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: A string containing a description of the dataset contents. This can optionally include information on the format in which the dataset is stored (e.g. pointer to a relevant schema).

    disclaimer

    A statement of applicability provided by the creator(s) informing users of the intended use and/or limitations of this dataset.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: A string containing the dataset disclaimer.

    material-component*

    A description of the chemical composition and structure of a substance in this dataset.

    Required Repeatable Type Extent Kind Rec. unit
    yes yes — — — —
    constituent*

    A chemical element included in the material component and its concentration.

    Required Repeatable Type Extent Kind Rec. unit
    yes yes — — — —
    species*

    A chemical element included in the material.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: A string containing the chemical designation of the element (e.g. "C").

    concentration*

    The fraction of the material composed of this element.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: A string containing the concentration in percent.

    phase*

    The phase of the material included in the dataset.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: A list of strings containing one or more of the following values: "Amorphous" – A solid material without crystalline order "Crystal" – A solid material characterized by a repeating pattern of atoms. "Quasicrystal" – A crystal-like material with short-range order, but without long-range order. "Molecule" – A finite group of atoms bonded together forming an independent unit. "Liquid" – A fluid structure (e.g. the molten state of a material) "Gas" – A structure where atoms are far apart and only interact during collisions. "Plasma" – A gas comprised of ions and electrons. Other user-specified value if none of the above apply.

    description

    An explanation of the nature of the material, e.g. a crystal structure designation, a chemical formula for a molecule, etc.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: A string containing the material description.

    microstructure

    The arrangement of phases, grains and defects in a material.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: A string containing a description of the microstructure of the material.

    computation*

    A description of a computer simulation used to generate data in the dataset.

    Required Repeatable Type Extent Kind Rec. unit
    yes yes — — — —
    method-class*

    The general category to which the computational technique belongs.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: A string containing one of the following values: "Electronic" "Atomistic" "Mesoscopic" "Continuum" "Data-driven" Other user-specified value if none of the above apply.

    Note:The categories listed above are based on the MODA standard.

    method*

    The computational materials science (CMS) approach used in the computation.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: A string containing one of the following values: For method-class "Electronic": "CC" – Coupled Cluster "QMC" – Quantum Monte Carlo "DFT" – Density Functional Theory "MBPT" – Many-Body Perturbation Theory methods (such as GW and BSE) For method-class "Atomistic": "MC" – Monte Carlo "MD" – Molecular Dynamics For method-class "Mesoscopic": "DDD" – Discrete Dislocation Dynamics "KMC" – Kinetic Monte Carlo "CGMD" – Coarse-grained MD For method-class "Continuum": "PF" – Phase Field For method-class "Data-driven": "ML" – Machine Learning Other user-specified value if none of the above apply.

    simulation-conditions*

    The interactions between the system being modeled and the rest of the world maintained during the computation.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —
    type*

    The nature of the simulation being performed, whether equilibrium, nonequilibrium, or nonstandard.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: String containing one of the following values defining the simulation conditions: "Equilibrium" – Thermodynamic equilibrium "Nonequilibrium" – Conforming to some definition of nonequilibrium thermodynamics "Other" – A simulation not fitting into the equilibrium and nonequilibrium categories. Note 1: The SubSubProperties listed below (aside from description) are provided as appropriate given the nature of the simulation. Providing a SubSubProperty means that its value is imposed on the simulation as an external constraint. Note 2:Units for dimensioned variables are to be given in the SI unit system.

    description

    Explanatory text clarifying the simulation type selection.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: A string containing the simulation type explanation.

    number-of-particles

    A count of atoms or other discrete entities comprising the material.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: An integer containing the number of particles N. Legacy unit: dimensionless

    volume

    The amount of space occupied by the material.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: A real number containing the volume V. Legacy unit: cubic meters (m^3)

    mass-density

    The total mass of the material divided by the volume it occupies.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: A real number containing the mass density 𝜌. Legacy unit: kilograms per cubic meter (kg/m^3)

    number-density

    The total number of particles comprising the material divided by the volume it occupies.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: A real number containing the number density n. Legacy unit: inverse cubic meter (1/m^3)

    cell

    The domain occupied by the material in the simulation (if fixed).

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: Ordered list of three vectors (a, b, c), each with three components, that define the simulation cell. The vectors (a, b, c) need not be orthogonal, and the magnitudes (│a│, │b│, │c│) are the supercell vector lengths. Legacy unit: meter (m)

    cell-reference

    The domain occupied by the material in the simulation in configuration relative to which strains are defined.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: Ordered list of three vectors (a0, b0, c0), each with three components, that define the cell used in the simulation in its reference configuration. The vectors (a0, b0, c0) need not be orthogonal, and the magnitudes (│a0│, │b0│, │c0│) are the reference cell vector lengths. Legacy unit: meter (m)

    cell-periodicity

    Specification of whether periodic boundary conditions are applied along the cell vector directions. This applies to both cell and cell-reference.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: Ordered list of three booleans (pa,, pb,, pc,), which are set to true if periodic boundary conditions are applied along the corresponding cell vectors (a, b, c). Legacy unit: dimensionless

    temperature

    A measure of the hotness or coldness of an external heat bath in thermal contact with the material.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: A real number containing the temperature T. Legacy unit: kelvin (K)

    stress

    A uniform force per unit current area, including both normal and shear components, applied to the material during the simulation through contact with an external loading device.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: An array of six real numbers containing the components of the (symmetric) Cauchy stress tensor σ in the following order: [σ11, σ22, σ33, σ23, σ13, σ12]. The stress component are expressed relative to an orthonormal basis (e1, e2, e3), where e1 is in the direction of a, e2 is in the direction of c╳a, and e3= e1╳e2, where (a, b, c) are the vectors defining the cell, which may not be orthogonal. Note 1: Requires the definition of the cell subproperty in order for a basis to be defined relative to which the tensor components are given. Note 2:The adopted sign convention is for tensile normal stresses to be positive, and compressive normal stresses to be negative. This implies that for a material subjected to a positive pressure p, the stress tensor components are [-p, -p, -p, 0, 0, 0]. Legacy unit: pascal (Pa)

    strain

    A deformation relative to a reference configuration imposed on the simulation cell expressed in the referential frame (Lagrangian strain tensor).

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: An array of six real numbers containing the components of the (symmetric) Lagrangian strain tensor Ein the following order: [E11, E22, E33, E23, E13, E12]. The strain component are expressed relative to an orthonormal basis (e1, e2, e3), where e1 is in the direction of a0, e2 is in the direction of c0╳a0, and e3= e1╳e2, where (a0, b0, c0) are the vectors defining the cell in the reference configuration, which may not be orthogonal. Note: Requires the definition of cell-reference in order for the basis to be defined relative to which the tensor components are given. Legacy unit: dimensionless

    strain-rate

    The derivative with respect to time of a deformation relative to a reference configuration imposed on the simulation cell expressed in the referential frame (Lagrangian strain rate tensor), which is constant throughout the simulation.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: An array of six real numbers containing the components of the (symmetric) Lagrangian strain rate tensor E in the following order: [E11, E22, E33, E23, E13, E12,]. The strain component are expressed relative to an orthonormal basis (e1, e2, e3), where e1 is in the direction of a0, e2 is in the direction of c0╳a0, and e3= e1╳e2, where (a0, b0, c0) are the vectors defining the cell in the reference configuration, which may not be orthogonal. Legacy unit: dimensionless

    Requires the definition of cell-reference in order for the basis to be defined relative to which the tensor components are given

    heat-flux

    The amount of thermal energy transferred to the material per unit area per unit time along a given direction.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: An array of three real numbers containing the components of the heat flux vector q. The heat flux component are expressed relative to an orthonormal basis (e1, e2, e3), where e1 is in the direction of a, e2 is in the direction of c╳a, and e3= e1╳e2, where (a, b, c) are the vectors defining the cell, which may not be orthogonal. Legacy unit: watts per square meter (W/m^2)

    temperature-gradient

    A physical quantity that describes the rate and direction of maximum temperature change per unit distance.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: An array of three real numbers containing the components of the temperature gradient vector ∇T. The temperature gradient component are expressed relative to an orthonormal basis (e1, e2, e3), where e1 is in the direction of a, e2 is in the direction of c╳a, and e3= e1╳e2, where (a, b, c) are the vectors defining cell, which may not be orthogonal. Legacy unit: watts per square meter (K/m)

    software*

    Identification of a computer package used to perform the calculations.

    Required Repeatable Type Extent Kind Rec. unit
    yes yes — — — —
    name*

    The name of the software package.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: A string containing the name of the software package (e.g. "VASP").

    version

    The version of the software package.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: A string containing the software version (e.g. "6.3.1")

    file

    Input or output file for the software package associated with the computation. This includes the input file used to perform the computation, associated data files, and output generated by the software package. Most important are input files to enable reproduction of the dataset.

    Required Repeatable Type Extent Kind Rec. unit
    no yes — — — —
    name*

    The file name.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: A string containing the name of the included file.

    description*

    A brief description of the file and its contents.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: A string containing the file description.

    contents

    The text and/or data contained in the file. Not required in case a link to the file is provided instead.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: A string containing the file contents.

    link

    A URI pointing to a permanent location of the file online.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: A string containing the file URI.

    citation

    Information that uniquely identifies a source being acknowledged.

    Required Repeatable Type Extent Kind Rec. unit
    no yes — — — —
    reference*

    Text that uniquely identifies the source of information being cited.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: A string containing the reference to the source.

    doi

    The digital object identifier (DOI) for the source.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: A string containing the source DOI.

    link

    A URI pointing to a permanent location of the source.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: A string containing the file URI.

    funding

    Information about received monetary support or other resources to generate the dataset.

    Required Repeatable Type Extent Kind Rec. unit
    no yes — — — —
    award-title*

    Name of the grant that provided funding to generate the dataset.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    funder*

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    award-number

    A funder identifier for the grant.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: A string containing the award number.

    related-content

    Other datasets that are connected to the current one in some manner.

    Required Repeatable Type Extent Kind Rec. unit
    no yes — — — —
    links*

    Pointer to one or more related datasets.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: A list of permanent pointers to related datasets (such as MatCore IDs, DOIs, URIs, etc.)

    description

    Explanation of the relationship between the related content and the current dataset.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: A string containing a description of the related content.

    provenance

    History of the dataset, detailing its origins and transformations.

    Required Repeatable Type Extent Kind Rec. unit
    no yes — — — —
    event-type*

    Description of change made to the dataset.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: A string containing one of the following values: "Initial creation" – Initial creation of the dataset "Admin update" – Editorial update to the dataset not requiring a version update (e.g. spelling correction). "Version update" – Change to the dataset or associated files requiring a new version "Metadata update" – Change to the metadata, but not the dataset itself. Other user-specified value if none of the above apply.

    date*

    The date and time when the change was made.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: A string containing the creation date in either format YYYY-MM-DD or YYYY-MM-DDTHH:mm:ssz (where "z" indicates UTC time zone) format (following the ISO 8601 Date and Time Format Standard).

    agent*

    Identity of the entity responsible for the change.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: A string containing the name or other designation identifying who or what is responsible for the change.

    comments

    Explanation for the change in provenance.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: A string containing an explanation for the nature of the changes leading to the revised provenance.

    checksum

    A digital fingerprint for the dataset of associated files.

    Required Repeatable Type Extent Kind Rec. unit
    no no — — — —

    Legacy: A list containing two strings: The name of a file, and the checksum for the file (e.g. the SHA-256 encoding for file).

    matcore-id*

    An identifier for the dataset.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: A string containing the MatCore identifier.

    matcore-date*

    The calendar date and time when this MatCore document was created.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: A string containing the creation date in either format YYYY-MM-DD or YYYY-MM-DDTHH:mm:ssz (where "z" indicates UTC time zone) format (following the ISO 8601 Date and Time Format Standard).

    license*

    A contract defining the terms and conditions under which the dataset can be used.

    Required Repeatable Type Extent Kind Rec. unit
    yes no — — — —

    Legacy: A string containing the dataset license in a format conforming to the SPDX Standard.

    Example: Minimal MatCore Metadata

    Dataset source: https://doi.org/10.60732/8e9bc5b0

    <?xml version="1.0" encoding="UTF-8"?>
<root>
  <creator>
    <name>Albert P. Bartók</name>
    <affiliation>Rutherford Appleton Laboratory</affiliation>
  </creator>
  <creator>
    <name>James Kermode</name>
    <affiliation>University of Warwick</affiliation>
  </creator>
  <creator>
    <name>Noam Bernstein</name>
    <affiliation>Naval Research Laboratory</affiliation>
  </creator>
  <creator>
    <name>Gábor Csányi</name>
    <affiliation>University of Cambridge</affiliation>
  </creator>
  <title>Si_PRX_GAP</title>
  <creation-date>2021-02-22</creation-date>
  <description>The original DFT training data for the general-purpose silicon interatomic potential described in the associated publication. The kinds of configuration that were included were selected based on intuition and past experience to obtain good coverage pertaining to a range of properties.</description>
  <material-component>
    <phase>crystal</phase>
    <constituent>
      <species>Si</species>
      <concentration>100</concentration>
    </constituent>
    <description>A variety of Si configurations including different phases, surfaces, vacancies, interstitials, dislocations and crack tips.</description>
  </material-component>
  <computation>
    <method-class>Electronic</method-class>
    <method>DFT</method>
    <simulation-conditions>
      <type>Equilibrium</type>
    </simulation-conditions>
    <software>
      <name>CASTEP</name>
    </software>
  </computation>
  <matcore-id>mc-ad83jsd3-1</matcore-id>
  <matcore-date>2026-02-14</matcore-date>
  <license>GPL-3.0-only</license>
</root>

    Note: The matcore-id format in the example is tentative and subject to change.
